# 场景 1：事务与隔离级别

> 目标：实测脏读 / 不可重复读 / 幻读，理解四种隔离级别与 MVCC 快照。

## 初始化

- 库：`train_tx`（utf8mb4）
- 表：`accounts(id 自增主键, name, balance)`
- 初始数据：`alice=1000`、`bob=1000`

## 三种读异常

| 异常 | 现象 | 在哪一级实测到 |
|---|---|---|
| 脏读 | 读到未提交的修改（900，回滚后凭空消失） | READ UNCOMMITTED |
| 不可重复读 | 同一事务两次读同一行，值变了（1000 → 900） | READ COMMITTED |
| 幻读 | 同一事务两次范围查询，行数变了（2 → 3） | READ COMMITTED |

### 深入：不可重复读 vs 可重复读（同一个问题，两种结局）

这俩名字像、又正好相反，容易绕晕。核心理解：**它们不是两件事，而是同一件事的两种结局。**

它们都在回答同一个问题：

> 同一个事务里，对同一行数据读两次，中间别人改了这行，两次读到的值一不一样？

- 两次**不一样** → 「不可重复读」（读的结果不能重复）
- 两次**一样** → 「可重复读」（读的结果能重复）

**用实测数据对一遍**（A 读 alice 两次，中间 B 把 alice 从 1000 改成 900 并提交）：

READ COMMITTED（不可重复读）：

```
A 第一次读 alice → 1000
B 改成 900 并提交
A 第二次读 alice → 900    ← 变了！两次不一样
```

REPEATABLE READ（可重复读）：

```
A 第一次读 alice → 1000
B 改成 900 并提交
A 第二次读 alice → 1000   ← 没变！两次一样
```

**机制（拍照比喻）**：

- READ COMMITTED：每次读都「抬头看现实世界」→ B 提交了，下次读就看到 900 → 不可重复。
- REPEATABLE READ：事务开始先「拍一张照片」，之后都看这张照片 → 照片里 alice 还是 1000 → 可重复。

一句话：**不可重复读 = 读两次会变；可重复读 = 读两次不变。**

### 深入：幻读（结果集多出 / 少了行）

幻读最容易和「不可重复读」混，差别在「什么变了」：

| | 不可重复读 | 幻读 |
|---|---|---|
| 谁引起 | UPDATE（改已有行） | INSERT / DELETE（增删行） |
| 什么变了 | 同一行的**值**变了 | 结果集的**行数**变了 |
| 直观表现 | 1000 → 900 | 2 行 → 3 行 |

一句话：**不可重复读 = 一行数据「变了脸」；幻读 = 凭空「多出/消失」一行。**

**为什么叫「幻」**：多出来的行像凭空冒出的幻影——第一次查时它还不存在，第二次查就突然出现了。

**用实测数据对一遍**：

```
会话 A（READ COMMITTED，开事务）：
  第一次：SELECT * FROM accounts → 2 行（alice、bob）
会话 B：INSERT charlie，提交
会话 A（同一事务再查）：
  第二次：SELECT * FROM accounts → 3 行（多了 charlie）
```

同一个事务里 2 行 → 3 行，多出的 charlie 就是「幻影行」。

**生活比喻**：仓库清点库存。第一次数 2 件，中间有人搬进 1 件，第二次数 3 件——同一个清点过程里，货架多了本来不存在的东西，这就是幻读。

**为什么 REPEATABLE READ 能挡住**：

- READ COMMITTED：每次读抬头看仓库 → 别人搬进来 charlie，下次就看到 → 幻读。
- REPEATABLE READ：事务开始先拍照 → 照片里只有 2 件 → 即使 charlie 搬进来，照片里还是 2 件 → 不幻读。

**三种读异常速记**：

| 异常 | 一句话 | 谁引起 |
|---|---|---|
| 脏读 | 读到别人没提交的假数据 | 未提交的 UPDATE |
| 不可重复读 | 同一行值变了 | 已提交的 UPDATE |
| 幻读 | 结果集多出/少了行 | 已提交的 INSERT/DELETE |

## 四种隔离级别对照

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| READ UNCOMMITTED | ✅ 可能 | ✅ 可能 | ✅ 可能 |
| READ COMMITTED | ❌ 禁止 | ✅ 可能 | ✅ 可能 |
| REPEATABLE READ（MySQL 默认） | ❌ 禁止 | ❌ 禁止 | 快照读 ❌ |
| SERIALIZABLE | ❌ 禁止 | ❌ 禁止 | ❌ 禁止 |

## 核心结论

1. MySQL 默认隔离级别是 **REPEATABLE READ**。
2. **MVCC**：每行数据是一条「版本链」，`UPDATE` 不覆盖旧值，而是新写版本、旧版本留在 undo log 里。
3. 读分两类：**快照读**（普通 `SELECT`）不加锁；**当前读**（`SELECT ... FOR UPDATE` / `UPDATE` / `DELETE`）加锁。
4. **READ COMMITTED**：每条 SELECT 生成新快照 → 每次都看最新已提交 → 产生不可重复读、幻读。
5. **REPEATABLE READ**：事务开始拍一张快照、全程复用 → 可重复读；快照读也免疫幻读。
6. **隐式提交**：`BEGIN` / `START TRANSACTION` 会提交当前已开事务；DDL（CREATE/ALTER/DROP/TRUNCATE）也会隐式提交。

## 实测记录（2026-09-03）

- 脏读：READ UNCOMMITTED 下读到未提交的 900，`ROLLBACK` 后变回 1000 ✅
- 不可重复读：READ COMMITTED 下同一事务 1000 → 900 ✅
- 可重复读：REPEATABLE READ 下同一事务两次都读 1000 ✅
- 幻读：READ COMMITTED 下 `COUNT(*)` 2 → 3 ✅
