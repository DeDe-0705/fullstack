# 场景 4：高并发库存扣减

> 目标：把事务、锁、乐观/悲观锁串成一条「秒杀扣库存」主线——防超卖、幂等、组合方案。

## 一、超卖问题

根源：「先查再扣」的 check-then-act 竞态。

```sql
SELECT stock FROM products WHERE id = 1;                  -- 查（check）
UPDATE products SET stock = stock - 1 WHERE id = 1;       -- 扣（act）
```

两步之间有空档，两个会话都查到 stock=1、都扣减，结果 stock=-1（超卖）。

## 二、原子更新（防超卖）

把「检查」和「扣减」合并进一条 UPDATE：

```sql
UPDATE products SET stock = stock - 1 WHERE id = 1 AND stock > 0;
```

`WHERE stock > 0` 让检查在行锁内完成，检查和扣减原子化，不会扣成负数；库存不足时影响 0 行。

## 三、幂等设计（防重复扣）

幂等 = 同一个操作执行 N 次，效果和执行 1 次一样。

核心武器：唯一约束。

```sql
CREATE TABLE orders (
  id         INT          NOT NULL AUTO_INCREMENT,
  order_no   VARCHAR(64)  NOT NULL,
  product_id INT          NOT NULL,
  quantity   INT          NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_order_no (order_no)
);
```

重复插入相同 order_no 报 `Duplicate entry`，重复请求在插入这步被拦，走不到扣库存。

## 四、完整幂等扣库存流程

```sql
-- 1. 插订单（幂等）
INSERT INTO orders (order_no, product_id, quantity) VALUES ('ORDER-001', 1, 1);
-- Duplicate entry → 重复请求，直接返回

-- 2. 原子更新扣库存（防超卖）
UPDATE products SET stock = stock - 1 WHERE id = 1 AND stock > 0;
-- 0 rows → 库存不足，回滚订单

-- 3. 更新订单状态
UPDATE orders SET status = 'paid' WHERE order_no = 'ORDER-001';
```

## 五、组合方案（秒杀标准答案框架）

| 问题 | 武器 |
|---|---|
| 超卖（扣成负数） | 原子更新 `WHERE stock > 0` |
| 重复请求（扣两次） | 唯一约束 `order_no` |
| 并发覆盖 / 丢失更新 | 乐观锁 version 或悲观锁 FOR UPDATE |
| 多实例分布式抢库存 | Redis 分布式锁 / MQ 削峰 |

一句话：**唯一约束保幂等 → 原子更新防超卖 → 锁控并发 → 高并发上 Redis 锁 + 队列削峰。**

## 六、实测记录（2026-09-03）

- 超卖：先查再扣，两个会话都读到 1，扣成 -1 ✅
- 原子更新：B 0 rows affected，stock 停在 0 ✅
- 幂等：重复插入 order_no 报 Duplicate entry ✅
