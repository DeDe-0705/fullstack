# 打卡场景题：查每人当天最早和最晚打卡时间

> 从一句简单需求出发，层层挖出「业务建模 + SQL 技巧 + 性能优化」。

## 需求

给定某天的员工打卡记录，查询每个人当天最早和最晚的打卡时间。

## 数据

```sql
CREATE TABLE attendance (
  id          INT PRIMARY KEY AUTO_INCREMENT,
  employee_id INT NOT NULL,
  punch_time  DATETIME NOT NULL,
  punch_type  VARCHAR(10),   -- 'in' 上班 / 'out' 下班（第二层才加）
  KEY idx_emp_time (employee_id, punch_time)
);
```

## 第一层：基础解法（GROUP BY + MIN/MAX）

```sql
SELECT employee_id,
       MIN(punch_time) AS first_punch,
       MAX(punch_time) AS last_punch
FROM attendance
WHERE punch_time >= '2026-09-04 00:00:00'
  AND punch_time <  '2026-09-05 00:00:00'
GROUP BY employee_id;
```

局限：假设「一天只打 2 次卡，最早=上班、最晚=下班」，多打卡就分不清。

## 坑 1：函数套列 → 索引失效

`WHERE DATE(punch_time) = '...'` 对列套函数，索引失效、全表扫描。

正确：直接对列做范围比较（列裸奔）。

## 第二层：业务建模——加 punch_type 区分上下班

多打卡（午休、补卡）需要「进/出」的语义，光有时间不够。

## 坑 2：多打卡 → 条件聚合

```sql
SELECT employee_id,
       MIN(CASE WHEN punch_type='in'  THEN punch_time END) AS check_in,
       MAX(CASE WHEN punch_type='out' THEN punch_time END) AS check_out
FROM attendance
WHERE punch_time >= '2026-09-04 00:00:00'
  AND punch_time <  '2026-09-05 00:00:00'
GROUP BY employee_id;
```

精髓：`CASE WHEN` 把不匹配的变 `NULL`，聚合函数忽略 `NULL`，实现"分类型取极值"。

## 坑 3：缺卡 → NULL 处理

没有 `out` 记录时，`check_out` 是 `NULL`。用 `COALESCE` 转默认值：

```sql
COALESCE(MAX(CASE WHEN punch_type='out' THEN punch_time END), '缺卡') AS check_out
```

## 第三层：窗口函数取第 N 次

`MIN/MAX` 和条件聚合都只能取极值，取「第 2 次打卡」就要用窗口函数：

```sql
SELECT employee_id, punch_time AS second_punch
FROM (
  SELECT employee_id, punch_time,
         ROW_NUMBER() OVER (PARTITION BY employee_id ORDER BY punch_time) AS rn
  FROM attendance
  WHERE punch_time >= '2026-09-04 00:00:00'
    AND punch_time <  '2026-09-05 00:00:00'
) t
WHERE rn = 2;
```

## 三种解法对比

| 解法 | 能做什么 | 局限 |
|---|---|---|
| `GROUP BY` + `MIN/MAX` | 取最早/最晚 | 多打卡就乱 |
| 条件聚合 `CASE WHEN` | 分类型取极值（in 最早 / out 最晚） | 只能取极值 |
| 窗口函数 `ROW_NUMBER` | 按序号取第 N 次 | 写法稍复杂 |

## 核心收获

1. **技术层**：GROUP BY 聚合、条件聚合（CASE WHEN）、窗口函数（ROW_NUMBER）。
2. **业务层**：多打卡需要 `punch_type` 区分上下班；缺卡需要 NULL 处理（COALESCE）。
3. **性能层**：WHERE 里函数套列导致索引失效，列要保持裸奔。
