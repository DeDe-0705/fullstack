# 场景 2：行锁与锁粒度

> 目标：实测 InnoDB 锁机制——行锁互斥、快照读 vs 当前读、索引决定锁粒度、三种锁、死锁。

## 一、快照读 vs 当前读

| 操作 | 类型 | 加锁？ | 被 X 锁挡住？ |
|---|---|---|---|
| 普通 `SELECT` | 快照读 | ❌ | ❌（读 MVCC 历史版本） |
| `SELECT ... FOR UPDATE` | 当前读 | ✅ X 锁 | ✅ |
| `UPDATE` / `DELETE` | 当前读 | ✅ X 锁 | ✅ |

- 核心结论：`UPDATE` / `DELETE` 天生就是当前读，自动加 X 锁，不用显式 FOR UPDATE。
- 金句：**读读不互斥、读写也不互斥，只有写写才互斥。**

## 二、索引决定锁粒度

InnoDB 的行锁加在「索引记录」上：

- WHERE 走索引 → **行锁**（只锁命中的行）
- WHERE 不走索引（全表扫描）→ **锁全表**（表级锁）

实测对比：

- `id`（主键索引）锁 id=1，另一会话锁 id=2 → 立刻返回（行锁）
- `name`（无索引）锁 alice，另一会话锁 bob → 卡住（表锁）

实战：`FOR UPDATE` 的 WHERE 必须走索引，否则锁粒度爆炸，高并发下性能雪崩、易死锁。

## 三、三种锁

```
索引 id 上的点：     1(alice)     2(bob)     → +∞
间隙 Gap：       (-∞, 1)     (1, 2)    (2, +∞)
```

- **Record Lock（记录锁）**：锁一个点，如 `id=1`。
- **Gap Lock（间隙锁）**：锁一段空隙，如 `(1, 2)`，防插入。
- **Next-Key Lock（临键锁）**：点 + 前面空隙，如 `(1, 2]`，RR 下当前读默认，防幻读。

**Next-Key Lock = Record Lock + Gap Lock 二者合一**：既锁「已有行」，又锁「前面的间隙」，所以它**既能挡 UPDATE，又能挡 INSERT**，这正是 RR 下范围查询能防幻读的原因。

三种锁对比：

| 锁 | 锁什么 | 防什么 |
|---|---|---|
| Record Lock | 已有的某一行 | 别人改这行 |
| Gap Lock | 记录之间的间隙 | 别人往间隙插新行 |
| Next-Key Lock | 行 + 前面间隙（二者合一） | 改 + 插都防 |

**书架比喻**：

```
[第1本]   [第2本]   (空位)
  alice     bob      ← 还能塞第3本
```

- Record Lock = 拿锁链锁住「第 2 本书」→ 别人不能动这本书。
- Gap Lock = 在「第 2 本后面的空位」放占位牌 → 别人不能往这里塞新书。
- Next-Key Lock = 锁链 + 占位牌一起上 → 改书、塞书都被挡。

**实战验证**（范围查询 `WHERE id > 1 FOR UPDATE`）：

- `UPDATE ... WHERE id = 2` → 卡住（Record Lock 生效）
- `INSERT` 一条新行 → 卡住（Gap Lock 生效）

选择规则：

- 等值查询命中唯一索引 → Record Lock
- 范围查询 / 非唯一索引 → Next-Key Lock
- READ COMMITTED 下禁用 Gap Lock（所以 RC 挡不住幻读）

## 四、死锁

- 现象：两个事务互相持有对方要的锁，循环等待，谁也走不了。
- 检测：等待图（wait-for graph），出现环即死锁。
- 回滚：InnoDB 挑「回滚代价最小」的事务回滚（通常是后触发死锁的那个）。
- 错误：`ERROR 1213 (40001) Deadlock found when trying to get lock`。

四个必要条件（缺一不可）：**互斥、持有并等待、不可剥夺、循环等待**。

避免死锁：

1. **统一加锁顺序**（最有效）：所有事务按同一顺序加锁。
2. **缩短事务**：锁持有时间越短越安全。
3. **应用层捕获 1213 重试**：死锁是小概率但不可避免的，标准做法是 catch 后重试。

## 五、实测记录（2026-09-03）

- 行锁互斥：FOR UPDATE 同一行，第二会话阻塞 ✅
- 快照读不阻塞：普通 SELECT 立刻返回 ✅
- UPDATE 是当前读：被 FOR UPDATE 挡住 ✅
- 行锁粒度：锁 id=1，另一会话锁 id=2 立刻返回 ✅
- 索引决定锁粒度：name 无索引 → 锁全表 ✅
- 间隙锁：范围 FOR UPDATE 挡住 INSERT ✅
- 死锁：反向加锁触发 `Deadlock found` ✅
