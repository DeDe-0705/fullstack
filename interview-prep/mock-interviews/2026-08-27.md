🟡 **commit 三步**：beforeMutation（getSnapshotBeforeUpdate）/ mutation（DOM）/ layout（useLayoutEffect）。

🟡 **批处理上下文**：React 17 只在事件处理器批处理，setTimeout/Promise 在上下文外不批处理；React 18 统一调度队列。

🟡 **浅比较失效**：内联对象/函数（引用每次变）；嵌套对象改内容不改引用。

🟡 **bailout 条件**：lanes 空 + childLanes 空 + props 没变（不是「或者」）。

🟡 **flag 术语**：Placement（新增/移动）、Deletion、Update，没有 ADD/DELETE/MOVE。

🟡 **状态设计**：状态集中导致全组件 re-render；组件拆分（状态局部化）是根本方案；单选共享用 store + selector 订阅布尔值。

## 标准答案速查

**1. 一次 setState 完整流程**

setState 创建 update（带 lane）→ 加入 hook.queue.pending → `markUpdateLaneFromFiberToRoot` 沿 return 向上冒泡标记祖先 childLanes → Scheduler 根据 lane 调度 → render 阶段（可中断：遍历构建 workInProgress、processUpdateQueue 算新 state、diff 打 flags）→ commit 阶段（不可中断：beforeMutation → mutation → layout，操作真实 DOM）→ 切换 current 指针。

**2. Hooks 原理 / useState 队列**

Hooks 状态存在 Fiber.memoizedState 单向链表上，render 按调用顺序取节点，所以不能条件调用。useState 的状态在 `Hook.memoizedState`，更新队列在 `Hook.queue.pending`（循环链表）；`processUpdateQueue` 按顺序遍历 update：action 是值则覆盖，是函数则用上一个结果作为 prev 累加。

**3. diff 三大策略 / key**

Tree diff（只比同层级，跨层级销毁重建）、Component diff（同类型继续比、不同类型替换）、Element diff（key 匹配列表）。flags：Placement（新增/移动）、Deletion（删除）、Update（更新）。key 用 index 在头部增删时 index 错位，导致状态串位。

**4. useEffect vs useLayoutEffect**

`useEffect` 在 commit 后、浏览器**绘制后**异步执行；`useLayoutEffect` 在 commit 后、**绘制前**同步执行。useLayoutEffect 用于读布局 + 改布局避免闪烁、恢复滚动位置。cleanup 在下一次 effect 执行前和组件卸载前执行。

**5. 受控 / 非受控**

受控数据源是 React state（value + onChange），非受控数据源是真实 DOM（defaultValue + ref）。受控只写 value 不写 onChange 会锁死输入框；`input type=file` 只能非受控（value 只读、安全限制）。

**6. 批处理 / 自动批处理**

React 17 及以前，批处理只在 React 事件处理器里（维护「批处理上下文」开关），setTimeout/Promise 回调在开关外、每次 setState 单独渲染；React 18 用统一调度队列，所有场景自动批处理。`flushSync` 强制同步渲染，典型场景是 setState 后立即读更新后的 DOM。

**7. memo / useMemo / useCallback**

React.memo 对 props 做浅比较（Object.is 逐属性）；失效场景：内联对象/函数（引用每次变）、嵌套对象改内容不改引用（该更新没更新）。useMemo 缓存计算值、useCallback 缓存函数引用。useCallback 单独用没意义，必须配 memo（否则子组件反正重渲染）。

**8. 并发 / 时间切片**

并发不是异步，是可中断的同步渲染 + 优先级调度。useTransition 手动标记「更新动作」低优先级、返回 isPending；useDeferredValue 自动让「值」滞后更新、无 isPending。时间切片只对并发更新（useTransition/useDeferredValue）生效，普通 setState 不可中断。

**9. 渲染边界 / 长任务**

复杂 updater 阻塞主线程产生长任务 > 16ms 掉帧。setState 后祖先被标记 childLanes（子树更新）、自身 lanes 为空，所以「路过」不重渲染。精准渲染边界靠 lane 冒泡 + bailout；bailout 条件 = lanes 空 + childLanes 空 + props 没变。

**10. 合成事件**

React 把原生事件封装成 SyntheticEvent，统一委托到 root 容器，事件冒泡后由 React 分发。`e.target` 是真正触发源，`e.currentTarget` 是当前处理事件的组件对应 DOM。React 17 从 document 改到 root 是为了多版本共存；React 17 起移除事件池。

**场景 1：大列表渲染**

首次慢 → 数据分页 + 虚拟列表（只渲染可视区）；滚动卡 → 虚拟列表 overscan + 卡片 memo + rAF 节流；点击全列表卡 → 状态提升导致全列表 re-render，用状态局部化（组件拆分）+ 单选 store + selector 订阅布尔值。

**场景 2：表单状态设计**

根因是 30 字段状态集中在同一父组件，任一字段变全表单 re-render。方案：组件拆分（每个字段独立 useState）+ useDeferredValue（输入与列表分层）+ 虚拟列表 + 防抖；提交汇总用「字段局部 useState + onChange 上报 + 父组件 useRef 收集」；生产用 react-hook-form。

**场景 3：Profiler 性能定位**

录制 → Ranked 视图按 self time 排序找最慢组件（total time 高但 self time 低是子组件拖慢）→ Why did this render 看 props/state/context 触发原因 → 优化后重新 profile 对比。若 Profiler 显示组件很快但页面仍卡，切 Chrome Performance 看 Main 线程的长任务、Layout/Paint、强制同步布局、GC。
