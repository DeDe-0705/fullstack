## 第七轮：Promise 与异步

### Q1：executor 什么时候执行？.then 回调什么时候执行？

**德德的回答：** executor 同步执行。then 的回调被推入微任务队列，等同步代码执行完后开始执行微任务。

**评分：⭐⭐⭐⭐⭐**

**精确化：** .then() 调用时注册回调，但回调是在 Promise 状态变为 fulfilled 后才被推入微任务。如果 Promise 已经 resolved，.then() 立即把回调推入微任务。

---

### Q2：Event Loop 时序题

```js
console.log(1)
new Promise(r => { console.log(2); r() }).then(() => console.log(3))
setTimeout(() => console.log(4), 0)
console.log(5)
```

**德德的回答：** 1、2、5、3、4

**评分：⭐⭐⭐⭐⭐**

**评价：** 宏/微任务优先级清晰，全对。

---

### Q3：嵌套微任务时序

```js
Promise.resolve().then(() => {
  console.log(1)
  Promise.resolve().then(() => console.log(2))
}).then(() => console.log(3))

Promise.resolve().then(() => console.log(4))
console.log(5)
```

**德德的回答：** 5、1、4、2、3

**评分：⭐⭐⭐⭐⭐**

**评价：** 三层嵌套微任务入队时序全对。Event Loop 是今天答得最稳的模块。

---

### Q4：all vs allSettled 的区别？

**德德的回答：** all 全部成功才返回，一个失败立即失败；allSettled 等全部执行完返回所有结果。第2个失败时，all 返回第二个失败结果，allSettled 返回所有三个结果。

**评分：⭐⭐⭐⭐**

**评价：** 准确。allSettled 返回 `{ status, value/reason }` 格式。

---

### Q5：race vs any 的区别？实际场景？

**德德的回答：** race 哪个先完成返回哪个；any 第一个成功返回成功，全失败才 reject。应用场景没想到。

**评分：⭐⭐⭐**

**补课：**
- race → 超时控制：`Promise.race([fetch(), timeout(5000)])`
- any → 多路冗余：`Promise.any([cdn1, cdn2, cdn3])` 取最快

---

### Q6：forEach + await 的输出顺序？

**德德的回答：** for 循环每隔 100s 打印；forEach 隔 300s 后立即打印。

**评分：⭐⭐⭐**

**纠正：** 代码里只有 forEach。forEach 不 await async 回调 → 三个 sleep 同时启动 → 100ms 后同时打印 1、2、3。done 立即打印。用 for...of 才是你描述的串行行为。

---

### Q7：并发控制——100个任务，最多同时3个？

**德德的回答：** 没思路，没接触过。

**评分：⭐**

**补课：** `Promise.race` + 补位模式。初始化 N 个任务 → 谁跑完补一个 → `await Promise.race(executing)` 等最快完成 → 循环直到全部完成。

---

### Q8：async/await 错误处理？try-catch 能捕获没 await 的 Promise 吗？

**德德的回答：** async await 用 try-catch，.then 用 .catch。错误一层层往上抛直到被捕获。

**评分：⭐⭐⭐⭐**

**补充细节：** try-catch **只对 `await` 后的 Promise 有效**。没 await 的 Promise.reject try-catch 捕获不到，必须用 .catch。reject 没任何捕获 → unhandledrejection。

## 面试后深度复盘：Promise 调度机制

面试暴露盲区后，德德对 asyncPool 进行了 6 轮追问，完整攻克了 Promise 的调度本质。

### 追问链路

```
Promise.all 源码 → then 第二个参数 = reject（一失即败）
  ↓
为什么 asyncPool 用 Promise.resolve().then(()=>task())？
  → task 是函数需调用 + 调用需异步 + 只有 .then 同时做到
  ↓
Promise.resolve(fn) vs .then(fn) vs new Promise(fn) 调用时机？
  → resolve=值不调用 / .then=异步回调 / new Promise=同步 executor
  ↓
asyncPool 为什么没有竞态条件？
  → 微任务不在同步代码中执行，for循环（排队）→ await（放行）
  ↓
Promise.all(results) 的作用？
  → 兜底：已 settled 立刻返回；未完成等最后一个
  ↓
await 做了什么？
  → 等 Promise settled → 拆出值
```
