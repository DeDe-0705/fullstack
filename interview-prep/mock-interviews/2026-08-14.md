## 第一轮：前端基础

### Q1：三栏布局（左 200 右 200 中间自适应）

**德德的回答：** flex：左右 `flex-basis` + `flex-shrink: 0`，中间 `flex: 1`；grid：首尾固定中间自适应；absolute：左右吸边、中间用 margin。优缺点和使用场景说不太出来。

**评分：⭐⭐⭐⭐**（方案全对，权衡缺失）

**纠正：**
- flex 方案注意中间 `min-width: 0`，否则长内容会撑破容器；适合常规页面布局
- grid 适合二维整体布局，三栏只是特例
- absolute 脱离文档流，左右栏不参与高度撑开，适合浮层 / 固定侧栏，不适合正文三栏

### Q2：事件循环输出题

**题目：** `start` / `setTimeout` / `Promise.then ×2` / `queueMicrotask` / `end`

**德德的回答：** `start、end、p1、micro、p2、timeout`（正确）

**评分：⭐⭐⭐⭐⭐**（输出正确）

**追问：** 在 p1 里再放一个 `Promise.resolve().then(() => console.log('p3'))`，输出顺序？

**回答：** `start、end、p1、micro、p3、p2、timeout`（正确）

**讲解：** p1 执行时 p3 同步入队；p1 返回后外层 Promise 才 resolve，p2 此时才入队，所以排在 micro 和 p3 之后；微任务队列清空后才执行下一个宏任务。

### Q3：URL 输入到首屏渲染 + 首屏慢定位

**德德的回答：** DNS 解析 → 下载静态资源 → DOM/CSSOM → 渲染树 → 计算位置 → 分层 → GPU 渲染；提到 “async 会阻塞渲染”；首屏慢从资源大小、chunk、Lighthouse 看 LCP。

**评分：⭐⭐⭐**（主链路对，细节错）

**纠正：**
- 缺少 TCP/TLS、HTTP 缓存、HTML 解析过程中 CSS 阻塞渲染、子资源加载、性能指标
- “async 会阻塞渲染”不准确：普通 script 阻塞解析；async 下载不阻塞、执行时可能阻塞；defer 解析完成后按顺序执行
- 首屏定位用分层框架：网络层（TTFB / CDN / 缓存 / 压缩）→ 资源层（路由分包 / Tree Shaking）→ 渲染层（render-blocking CSS / LCP / 图片 / 长任务）→ 交互层（TBT / INP）

## 第二轮：Vue 核心原理

### Q1：Proxy vs defineProperty / reactive vs ref / shallowRef

**德德的回答：** defineProperty 只能劫持已有属性，数组索引和 length 无法感知，初始化递归开销大；Proxy 代理整个对象，支持新增删除和数组、惰性响应。ref / reactive 差异不太明白；shallowRef 用于只关注第一层变化。

**评分：⭐⭐⭐⭐**（Proxy 部分强，ref/reactive 是盲区）

**纠正：** `reactive` 只能接收对象，重新赋值整个对象会丢响应；`ref` 把值包装成 `{ value }`，对象内部走 `reactive`，脚本里 `.value`、模板自动解包；`shallowRef` 内部对象不被代理，深层修改不触发，只有替换 `.value` 触发，必要时用 `triggerRef`。

### Q2：computed vs watch

**德德的回答：** 核心区别不太明白；computed 有 dirty 标签；区分场景看是否有返回值。

**评分：⭐⭐**（本轮最大盲区）

**纠正：** computed 是“派生状态”，同步纯函数 + 缓存 + 懒计算，适合模板展示；watch 是“副作用”，适合异步、DOM 操作、防抖、需要 old/new 值。不是“有没有返回值”。computed 不能发异步请求，getter 返回 Promise 不会自动 await，结果也不会触发更新；异步派生用 watch + ref 或 VueUse `computedAsync`。

### Q3：key 与 Vue3 diff

**德德的回答：** index 会导致组件复用到错误位置；Vue3 从双端 diff 变成快速 diff，具体不清楚。

**评分：⭐⭐⭐**（结论对，机制缺）

**纠正：** index 在头部插入 / 重排时，组件实例和内部状态（输入框、滚动、动画）被错误复用。Vue2 是双端 diff；Vue3 快速 diff = 头尾同步 + key 映射 + 最长递增子序列，配合编译期 patchFlag、静态提升、事件缓存。

### Q4：组件通信 / v-model

**德德的回答：** 正确做法是 emit；v-model 是 props 和 emit 的结合。

**评分：⭐⭐⭐⭐**（对，缺 defineModel）

**纠正：** `v-model` 默认 = `modelValue` + `update:modelValue`；`v-model:title` = `title` + `update:title`；`defineModel()` 把 prop + emit 封装成可读写 ref，支持修饰符。

### 追问与场景题

**Q：shallowRef 存对象，修改对象内部属性会更新吗？**

回答：不会，原因不清楚。

纠正：只劫持 `.value`，内部对象没有被 Proxy 代理，所以深层修改不触发；需要时用 `triggerRef` 手动触发。

**Q：computed 里能发异步请求吗？**

回答：可以但会告警，不能 async/await。

纠正：不是“能用只是警告”，是错误用法。getter 必须同步返回值，返回 Promise 模板拿到的是 Promise 对象，结果不会触发更新。正确做法是 watch + ref，或 VueUse `computedAsync`。

**Q：用 index 作 key，头部插入一条数据时具体发生什么？**

回答：原 index 0 的输入框状态会复用到新增数据上。

评分：✅ 正确。新增行复用了旧行的组件实例，残留旧输入、焦点和内部状态。

**Q：自定义组件 `v-model:title` 怎么写？**

回答：定义 `title` prop、触发 `update:title` 事件；`defineModel` 省略声明。

评分：✅ 正确。

**场景题：搜索竞态。**

回答：防抖 + AbortController。

纠正：完整答案 = 防抖减少请求 + AbortController 取消在途 + 请求序号 / 时间戳保证最后一次胜出。

**场景题：10 万行数据渲染。**

回答：图片懒加载；虚拟滚动只渲染可视区域。

纠正：虚拟滚动核心正确，还需 overscan 缓冲。其他优化：分页 / 无限加载、分片渲染、Web Worker 计算、Canvas 渲染、CSS `content-visibility: auto`、静态数据记忆化。

## 第三轮：弱项抽查

### Q1：Vue 开发者去 React 团队，最先补什么？

**德德的回答：** Hook 概念、TSX、数据驱动视图更新；不太清楚。

**评分：⭐⭐**（停留在名词层）

**纠正：** 三个核心差异：
1. **不可变数据 + 整体 re-render**：`setState` 产生新状态，父组件渲染会带动子组件，需要 `memo` / `useMemo` / `useCallback` 手动优化；Vue 是可变数据 + 自动依赖追踪
2. **Hooks 依赖数组 + 闭包**：`useEffect` 不会自动追踪依赖，需要手动声明 deps，容易闭包过期值；对应 Vue `watch` / `watchEffect` / `computed` 的自动追踪
3. **JSX 是表达式而非模板**：`className`、style 对象、事件、key、Hooks 调用顺序规则；Vue 模板有编译期优化（PatchFlags / 静态提升），React 主要靠运行时 Fiber / 并发

### Q2：Java 全栈链路

**德德的回答：** 浏览器 → Controller → Service → DAO → MySQL → 返回；Eureka 服务注册，Feign 调用；Apollo 配置中心（数据库密码等敏感配置）；Kafka 消息中心，监听事件消费。

**评分：⭐⭐⭐⭐**（链路正确，术语需更精确）

**纠正：** 完整链路：浏览器 → Nginx → 网关 / 服务 → Controller → Service → DAO/MyBatis → MySQL → 返回；人员信息通过 Feign 调公共服务（内部 Redis 缓存）。Eureka 是服务注册发现中心，客户端本地缓存实例列表，AP 型；Apollo 负责多环境隔离、动态刷新、审计，密钥需加密存储；Kafka 是生产者发布到 topic、消费者订阅，至少一次语义需要消费幂等，用于跨服务异步解耦。

### Q3：RAG 和微调的区别

**德德的回答：** RAG 是对文本切分后找和目标向量更接近的片段；微调不太明白。

**评分：⭐⭐**（RAG 方向对，微调盲区）

**纠正：** RAG = 检索增强生成，把外部知识切分 → Embedding → 向量检索 → 注入上下文，知识可随时更新、无需训练、成本低，解决“模型不知道”的问题；微调 = 用领域数据更新模型权重，解决“能力、风格、格式”问题，需要数据集、成本高、知识更新要重训。口诀：**RAG 管“知道什么”，微调管“怎么说话 / 做事”**。
