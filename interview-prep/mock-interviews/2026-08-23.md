## Q1：Proxy 替换 defineProperty 的原因 / Proxy 的局限 / Vue3 的补救（美团 2026 二面真题）

**回答摘要**：新增/删除属性无法感知、数组长度变化需要重写方法、初始化递归性能差；局限答了"只能代理对象（→ref）、Object.freeze 无法 set"；补救不知道。

**评分：⭐⭐⭐（70%）**

**纠正与补齐**：
- ❌ 术语错误："初始化把所有属性加到依赖池" —— **劫持 ≠ 依赖收集**。递归做的是劫持（加 getter/setter），依赖收集是运行时读取属性才发生
- 📚 补齐局限→补救对照：基本类型 → ref；代理对象 ≠ 原对象 → toRaw + proxyMap 缓存；**Map/Set 方法调用走不到 get/set 拦截 → get 拦截器里检测集合并返回包装方法（内部 toRaw + 手动 track/trigger）**——分水岭考点

---

## Q2：reactive 嵌套对象的代理时机 + 未消费数据的开销

**回答摘要**：认为 reactive() 时第一层属性都被代理了；认为 list 会产生开销。

**评分：⭐（掉进考点坑）**

**纠正**：
- ❌ `reactive()` 只代理**最外层对象本身**，嵌套对象在被 **get 访问时**才递归包装（惰性代理，proxyMap 缓存防重复）
- ❌ 模板只用 `user.name` 时，`list` **零响应式开销**——get 从未触发，就是普通数据
- ✅ 这是对 Vue2"初始化全量递归劫持"的最大改进：按需付费

---

## Q3：依赖收集的三层数据结构 + 为什么用 WeakMap

**回答摘要**：targetMap→depsMap→dep 结构答对；认为 dep 存"视图元素"；认为 WeakMap 回收"视图卸载的元素"。

**评分：⭐⭐⭐（结构对，概念漂移两处）**

**纠正**：
- ❌ dep 存的是 **effect（渲染函数/computed 求值/watch 回调）**，不是 DOM 元素。链路：属性变化 → trigger 找 effect → 执行 → 渲染 effect 产出 vnode → patch
- ❌ WeakMap 的 key 是**原始数据对象 target**。回收链：组件销毁 → target 失去外部强引用 → WeakMap 弱引用不阻止回收 → 整条依赖链失去入口被 GC。普通 Map 会反向"续命" → 内存泄漏

---

## Q4：computed 的两层短路（2026 高频深挖）

**回答摘要**：同值赋值不重算、不更新（结论对）；归因到"computed 判断值相同返回缓存"（位置错）；第二层场景靠 diff 兜底（错）；不知道第二层。

**评分：⭐⭐（结论对，机制位置错）**

**纠正**：
- 第一层短路在**数据源 set**（ref/reactive 拦截器里 `hasChanged`/Object.is），trigger 根本不执行，computed 连 dirty 都不置位
- 第二层短路在 **computed 求值之后**：`hasChanged(新结果, 旧结果)` 为 false → 不 triggerRefValue → 渲染 effect 不执行 → 没有 vnode、没有 diff
- "diff 同 vnode 不 patch"是第三道保险，但前两层短路下渲染 effect 根本不跑——用它解释是答非所问

---

## Q5：PatchFlag / BlockTree / 静态提升（编译优化三连）

**回答摘要**：三问全空白，复述检验也未通过。

**评分：☆（本轮最大盲区）**

**已教学（30 秒极简版）**：
- 编译器像提前预习的考生：**永远不变的节点**（h1）→ 静态提升，vnode 只造一次，HOISTED 标记 patch 直接跳过

- v-if/v-for 是结构边界 → 产生新 block（BlockTree）保证正确性

## Q6：useSearch 场景——watch vs watchEffect / 竞态内建机制 / 竞态解法

**回答摘要**：选 watch 理由成立✅；内建机制答成"对比 old/new"❌；提到 AbortController✅、loading❌。

**评分：⭐⭐⭐（选择对，核心考点 onCleanup 未命中）**

**纠正**：
- **onCleanup 是 watch 回调第三个参数**（3.5 也有全局 onWatcherCleanup），清理函数在下一次回调前 / watcher 停止（含组件卸载）时自动执行
- 标准解法：onCleanup 里 `clearTimeout`（防抖）+ `controller.abort()`（竞态），一个钩子解决三个需求
- ❌ loading 和 old/new 比对都不能解决竞态——竞态是**响应到达顺序**问题
- 备用解法：闭包版本号 token（旧响应自我作废）

## Q7：v-model 本质 / defineModel 前的写法 / defineModel 穿透链路

**回答摘要**：本质（modelValue + update:modelValue）✅；旧写法方向✅；穿透链路不知道。

**评分：⭐⭐⭐⭐（1、2 对）**

**纠正**：
- 穿透是一次**事件往返**：set → emit → 父组件更新自己的变量 → 新 prop 流回 → get 读到新值（内部 local value 兜底 prop 往返延迟）
- 单向数据流没有被打破——子组件从未直接改父状态
- defineModel = props + emit + **customRef 包装**（框架自己在用 customRef）

# 模拟面试 · 第 10 轮：Vue3 原理复测（同日晚间）

> 形式：只考第 9 轮空白点，全部变体出题。5 问。复习材料：Vue3深度原理.md 第一、二章 + 1.7 节补救 API + 盲区清单。

## R1：PatchFlag / BlockTree / 静态提升（模板阅读题）

**回答摘要**：三个节点 PatchFlag 全对（h2 静态 / p 动态文本 / span 动态 class）；"style 是固化字符串不参与 patch"✅；dynamicChildren 说 p、span、ul、li 都进（li 归属错）；v-if 新 block 只答"保证正确性"；PatchFlag 与 BlockTree 分工方向对。

**评分：⭐⭐⭐⭐（75%，上午 ☆ → 75%，回血最大的一题）**

**纠正**：
- ❌ **最近 block 原则**：li 属于 v-for fragment 自己的 block，不冒泡到根 block。根 block 的 dynamicChildren 只有 [p, span, ul 的 fragment]
- ❌ v-if 机制没答出：条件表达式重新求值 → 旧分支整个 block 卸载、新分支挂载（边界处退化正常 diff），根 block 名单结构不变
- 精确分工：**PatchFlag 管单个节点内部更新什么（属性粒度），BlockTree 管整棵树更新哪些节点（结构粒度）**

## R2：惰性代理 + toRaw + proxyMap + ECharts 场景

**回答摘要**：嵌套对象未代理✅；改 raw 不触发更新（机制方向对）✅；reactive(reactive(x)) 成立但机制说不出；ECharts 场景答"普通变量 / markRaw"✅但**markRaw 拼写第二次写错（markRow）**。

**评分：⭐⭐⭐⭐（85%）**

**纠正**：
- proxyMap 两个短路：`isProxy(target) → 原样返回`；`proxyMap.get(target) 缓存命中 → 返回已有代理`。同一原对象全局唯一代理实例
- ECharts 后果精确版：实例内部 this 判断/私有字段/内部缓存被代理打乱 → 渲染异常 + 上万属性全被代理的性能暴跌
- markRaw 拼写：已错两次，白板高风险

## R3：computed 两层短路（变体场景 A/B）

**回答摘要**：场景 A（同值赋值）——ref 层判断、不 trigger、dirty 不置位，全对✅；场景 B（值变结果不变）——重算发生、结果相同不更新视图，全对✅；两层区别表述略松。

**评分：⭐⭐⭐⭐⭐（90%，本轮最佳）**

**精确版**：第一层挡"依赖通知"（computed 零成本）；第二层挡"向下游传播"（computed 付出重算成本但截停在中游）。两道闸门，一在数据源 setter，一在 computed 出口。

## R4：onCleanup 竞态手写

**回答摘要**：清理时机两个答对✅；手写未完成（"全局 AbortController"表述错，"不执行返回内容"混淆 abort 语义）；token 版本不知道。

**评分：⭐⭐⭐（55%，本轮最弱）**

**纠正**：
- controller 是**每次回调内新建**（闭包作用域对应"这一次请求"），不是全局
- `abort()` 掐断传输本身：fetch 直接 reject（AbortError），响应**根本不会到达**，不是"回来了但不用"
- 时机配对：切新值时 **Vue 先跑上一次的 onCleanup（掐旧请求）再执行新回调**
- token 模板核心一行：`if (current !== latestId) return`——响应回来对编号，过期自我作废
- **行动项：两个竞态模板（AbortController 版 + token 版）各默写一遍**

## R5：术语总清算（effect / 更新链路 / WeakMap / 劫持 vs 收集）

**回答摘要**：dep 存 effect✅（"元素"已纠正）；劫持在声明时、收集在读取时✅；更新链路停在"通知 effect 更新视图"（跳过 vnode/diff/patch 四环）；WeakMap 答出关键词无步骤（且混入 WeakSet 干扰项）。

**评分：⭐⭐⭐（70%）**

**纠正**：
- 完整链路（满分结构，需背）：set 拦截 → hasChanged → trigger（targetMap→depsMap→dep）→ 渲染 effect 进异步队列 → 微任务 flush 重执行渲染函数 → 新 vnode → patch（沿 dynamicChildren + PatchFlag）→ 真实 DOM
- WeakMap 回收四步：①effect stop 移除依赖 ②target 失去强引用 ③弱引用不阻止回收 ④GC 回收 target，整条依赖链失去入口
- 普通 Map 后果精确表述：注册表强引用反向"续命"，泄漏整条链

# 模拟面试 · 前端基础 + Vue 综合（10 问 + 6 追问）

> 日期：2026-08-23 ｜ 形式：场景题 + 追问 ｜ 范围：浏览器原理 / 网络与 HTTP / 存储缓存 / Vue3 基础
> 说明：与同日「第 9/10 轮 Vue3 专题」为不同场次，本场覆盖前端基础广度 + Vue 高频 API。

## Q1：URL 到页面渲染完整流程 —— ⭐⭐⭐

- 答对：DNS → 请求资源 → DOM/CSSOM → render tree → 布局 → 渲染。
- 纠正：漏 TCP 三次握手 + TLS 握手；漏 HTTP 缓存；漏 CSS 阻塞渲染 / JS 阻塞解析 / CSS 间接阻塞 JS；漏 Paint（Layout → Paint → Composite，分层在 Composite）。

## Q1.1：强缓存 vs 协商缓存 —— ⭐⭐

- 纠正：`no-store` ≠ 协商缓存（no-store=不缓存，no-cache=协商）；强缓存命中不发请求、状态码 200（from memory/disk cache）；`Expires`（HTTP/1.0 绝对时间）优先级低于 `max-age`（HTTP/1.1 相对秒数）。

## Q1.2：ETag vs Last-Modified —— ⭐⭐⭐⭐

- 补：Last-Modified 秒级精度 → 1 秒内改多次误判 304；时间变内容没变 → 误判 200 全量重传；ETag 强/弱验证器；If-None-Match 优先。

## Q2：Cookie / localStorage / sessionStorage / IndexedDB —— ⭐⭐

- 纠正：作用域是「同源 Origin（协议+域名+端口）」，不是「二级域名」，子域不共享；Cookie 生命周期由 Expires/Max-Age 决定（不设=会话级）；Cookie 作用域是 Domain+Path；SameSite 控制跨站携带（防 CSRF）；IndexedDB 拼写 + 异步/事务/索引/二进制。

## Q2.1：Cookie 安全属性 httpOnly/Secure/SameSite —— ⭐⭐⭐⭐⭐

- 全对。

## Q3：回流 / 重绘 / 合成 —— ⭐⭐⭐

- 纠正：opacity 是「合成」不是「重绘」（和 transform 一样）；是 `requestAnimationFrame`（非 requestIframe）；漏「读写分离」。

## Q3.1：强制同步布局 layout thrashing —— ⭐⭐⭐

- 纠正：写 style 不直接回流（只标记脏），下次读布局属性才强制 flush；核心解法是读写分离（先读后写），rAF 只是实现方式之一。

## Q4：ref vs reactive —— ⭐⭐⭐

- 纠正：解构时两者都丢（toRefs 保）；内部实现——ref=class + getter/setter（.value），对象内部走 reactive（toReactive）；reactive=Proxy 拦截属性读写。

## Q4.1：shallowRef / shallowReactive —— ⭐⭐⭐

- 纠正：shallowReactive 是「第一层属性响应」，不是「整体替换」；补 triggerRef、markRaw（图表实例更常用 markRaw）。

## Q5：computed vs watch —— ⭐⭐⭐⭐

- 补：computed=纯函数无副作用 + 缓存 + 懒计算；watch=副作用（异步/DOM/防抖）；computed 发异步是错误用法。

## Q6：nextTick 原理 —— ⭐⭐⭐⭐⭐

- 全对。补：队列去重 + 微任务 flush + nextTick 回调排在组件更新后。

## Q7：v-model / defineModel —— ⭐⭐⭐⭐⭐

- 全对。笔误 `update:modeValue` → `update:modelValue`。

## Q8：跨域 / CORS —— ⭐⭐⭐

- 纠正：同源=协议+域名+端口；同源策略防「跨源读数据」；CORS 四个响应头；`application/json` 是非简单请求（触发预检 OPTIONS）。

## Q8.1：跨域拦请求还是响应 —— ⭐⭐⭐⭐⭐

- 全对（拦响应，请求照发；预检意义 = 避免有副作用请求已执行却收不到结果）。

## Q9：事件循环输出题 —— ⭐⭐⭐⭐⭐

- 输出全对。提醒：只报结果不够，要讲过程（Promise executor 同步、每宏任务后清空微任务）。

## Q10：搜索防抖 + 请求竞态 —— ⭐⭐⭐⭐

- 纠正：loading 不能减少请求频率/解决竞态；竞态要「AbortController + 请求序号（token）」双保险；防抖/节流区别答对。
