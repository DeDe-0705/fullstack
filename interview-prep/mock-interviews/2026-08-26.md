## 一、代码题：聊天室闭包陷阱（8/10）

**题**：useEffect 里 `setMessages([...messages, msg])`，依赖 `[roomId]`，找 bug。

**答对**：主 bug（快照覆盖）、函数式更新、key=index、status 复位意识。
**失分**：
1. 症状因果偏：「同一时刻收到多条消息才丢」→ 实际**无论何时**都覆盖，列表永远只显示最后一条（闭包里的 `messages` 恒为 `[]`，重渲染不更新闭包）。
2. 「上一次渲染的快照」→ 应为 **effect 执行那一刻的快照**。
3. 修法权衡缺失：函数式更新 vs 把 `messages` 加依赖（后者引发 socket 反复断连重连的 effect 风暴）。
4. 隐藏 bug：`socket.on` 的监听器没在 cleanup 里 `off`，切房间叠加监听器。

**关键教训**：依赖数组权衡 = 撒谎导致闭包过期 vs 诚实导致 effect 风暴；函数式更新绕开整个权衡。

## 二、场景题：列表打字卡顿（5/10）

**答对**：useDeferredValue 选型 + 优先级语义、虚拟化组合。
**失分**：
1. **审题硬伤**：题设是本地数据，答了「请求竞态取消」——套搜索场景八股模板，真实面试被判「没在听题」。
2. **概念偏差**：「startTransition 包裹请求的方法」→ 包的是 **state 更新**，React 调度渲染不调度 IO；异步数据接入渲染走 `use(promise)` + Suspense。
3. 定位只报工具名：Profiler 要看 commit 耗时 + render 原因，并分瓶颈类型（计算 / 渲染量 / IO）。
4. 附加全丢：防抖（时间维降频率、丢实时性）vs useDeferredValue（调度维降优先级、丢短暂一致性）、useMemo 此场景无效的原因。

## 三、原理题：重渲染 bailout（3/10）

**账本正确答案**：点击 3 次 → Parent 4 次 / Child 4 次 / MemoChild 1 次。默认规则：**父渲染，子无条件重渲染**（React 默认不看 props）；memo 在 render 前插 props 浅比较（逐个 Object.is），全等 → bailout，函数体不执行。

**bailout 四边界**（答出 Context 穿透，其余不知）：

| 场景 | 挡得住吗 |
| --- | --- |
| props 浅比较通过 | ✅ |
| props 引用不稳定（内联对象/函数） | ❌ memo 失效 |
| 自身 state 变化 | ❌ |
| Context 变化 | ❌ 穿透 memo |

**有价值的一半**：「render 函数执行 ≠ DOM 更新，被 diff 过滤」——执行成本照样花，贵的是前半段。

## 四、设计题：六状态容器（5.5/10）

| 状态 | 我选 | 判 |
| --- | --- | --- |
| 搜索关键词 | 本地 | △ 漏 URL 信号 |
| 列表数据 | TanStack Query | ✅ |
| 分页页码 | 服务端状态库 | ❌ 导航状态，非服务端数据 |
| 弹窗开关 | URL | ❌ 瞬时 UI 应本地——与关键词信号接反 |
| 勾选行 | 本地 | ✅ 漏「被列表外消费则提升」边界 |
| 用户信息 | 全局 store | ✅ Context 亦可 |

**决策树**：①服务端拥有 → Query 类；②刷新/分享/回退要保留 → URL；③共享半径：树内 → 本地/提升，跨页高频 → store，低频全局 → Context；④瞬时 UI → 本地，永远不进全局。
页码挪 URL 的信号：可分享（发链接带页码）、可恢复（刷新留在当前页）、回退键、URL 埋点。
