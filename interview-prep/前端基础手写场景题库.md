## 一、事件循环与异步

### 题 1：事件循环输出顺序

```js
console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => console.log('3'));
console.log('4');
```

**输出**：`1 4 3 2`

**解析**：
- `1`、`4` 是同步代码，先执行；
- `Promise.then` 是**微任务**，同步栈清空后、下一个宏任务前执行 → `3`；
- `setTimeout` 是**宏任务**，本轮末尾才执行 → `2`。

**一句话规则**：同步 > 微任务（Promise.then / queueMicrotask）> 宏任务（setTimeout / setInterval / I/O）。

**追问加深（必会）**：`async/await` 里的 `await` 相当于 `Promise.then`，会让出到微任务；`process.nextTick`（Node）优先级高于 `Promise.then`。

### 题 2：手写 Promise.all

```js
Promise.myAll = function (iterable) {
  return new Promise((resolve, reject) => {
    const arr = Array.from(iterable);
    const result = new Array(arr.length);
    let count = 0;
    if (arr.length === 0) return resolve(result);
    arr.forEach((item, index) => {
      Promise.resolve(item).then((val) => {
        result[index] = val;   // ① 用索引保序，千万别 push
        count++;
        if (count === arr.length) resolve(result);
      }, reject);             // ② 任一失败立即 reject
    });
  });
};
```

**三个防坑点**：`result[index]` 而非 `push`（保证输出顺序和输入一致）；`count` 计数而非直接判断；某个元素非 Promise 时用 `Promise.resolve` 包装。

**追问**：`race` 怎么做？（返回第一个 settle 的）；`allSettled` / `any` 的区别？

### 题 3：带并发限制的调度器 asyncPool（字节高频）

```js
async function asyncPool(limit, tasks) {
  const ret = [];
  const running = new Set();
  for (const task of tasks) {
    const p = Promise.resolve().then(() => task());
    ret.push(p);
    running.add(p);
    const done = () => running.delete(p);
    p.then(done).catch(done);
    if (running.size >= limit) {
      await Promise.race(running);   // 跑完一个再放行下一个
    }
  }
  return Promise.all(ret);
}
```

**核心**：用 `Set` 记录正在执行的任务，满了就 `await Promise.race` 等第一个完成，保证最多 `limit` 个并发。

**追问**：如果不限制并发会怎样？（瞬间打满连接池/数据库）；`Promise.race` 为什么是"等任一个"？

## 二、闭包 / this / 作用域

### 题 4：经典 for + setTimeout 输出

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 输出：3 3 3  （var 是函数作用域，回调共享同一个 i，循环结束时已是 3）

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 输出：0 1 2  （let 块级作用域，每次迭代独立绑定）

// 用 IIFE 修 var（面试让写）
for (var i = 0; i < 3; i++) {
  (function (j) { setTimeout(() => console.log(j), 0); })(i);
}
```

**一句话**：`var` 函数作用域共享，`let` 每次迭代创建独立绑定；经典解法 `let` 或 IIFE 传参形成闭包。

### 题 5：this 指向（快速判断）

```js
const obj = { a: 1, foo() { console.log(this.a); } };
obj.foo();            // 1  （对象方法：this = obj）
const fn = obj.foo;
fn();                 // undefined / window（非严格）（默认绑定）
obj.foo.call({ a: 9 }); // 9  （call 指定 this）
const bar = obj.foo.bind({ a: 7 });
bar();                // 7  （bind 返回新函数，永久绑定）
const arrow = () => console.log(this.a); // this = 外层词法 this，箭头函数没有自己的 this
```

**优先级**：`new` > `bind/call/apply` > 对象方法调用 > 默认绑定（严格模式 undefined）。

**追问**：箭头函数和普通函数的 this 区别？`new` 时 this 指向谁？

## 三、手写工具函数

### 题 6：防抖 debounce（含 immediate）

```js
function debounce(fn, wait = 300, immediate = false) {
  let timer = null;
  return function (...args) {
    const callNow = immediate && !timer;
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      if (!immediate) fn.apply(this, args);
    }, wait);
    if (callNow) fn.apply(this, args);
  };
}
```

**场景**：搜索输入、resize、表单校验——**只关心最后一次**。

**追问**：`immediate` 有什么用？（首次立即执行+期间不触发）；防抖和节流的区别？

### 题 7：节流 throttle

```js
function throttle(fn, wait = 300) {
  let lastTime = 0;
  return function (...args) {
    const now = Date.now();
    if (now - lastTime >= wait) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}
```

**场景**：滚动加载、按钮防连点、mousemove——**按固定频率触发**。

**一句话区分**：防抖"最后一下才做"，节流"固定频率做"。

**追问**：如果要"首次立即 + 结束后再执行一次"怎么组合？（时间戳版 + 定时器版结合）

### 题 8：深拷贝（循环引用 + 特殊类型）

```js
function deepClone(value, cache = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value; // 基本类型/函数原样
  if (value instanceof Date) return new Date(value);
  if (value instanceof RegExp) return new RegExp(value.source, value.flags);
  if (cache.has(value)) return cache.get(value);                 // 循环引用
  if (value instanceof Map) {
    const m = new Map();
    cache.set(value, m);
    value.forEach((v, k) => m.set(deepClone(k, cache), deepClone(v, cache)));
    return m;
  }
  if (value instanceof Set) {
    const s = new Set();
    cache.set(value, s);
    value.forEach((v) => s.add(deepClone(v, cache)));
    return s;
  }
  const result = Array.isArray(value) ? [] : {};
  cache.set(value, result);
  for (const key of Reflect.ownKeys(value)) {
    result[key] = deepClone(value[key], cache);
  }
  return result;
}
```

**考点**：用 `WeakMap` 缓存已克隆对象解决**循环引用**；`Reflect.ownKeys` 连 Symbol 一起拷；`Date/RegExp/Map/Set` 单独处理；函数等原样返回。

**追问**：为什么不直接 `JSON.parse(JSON.stringify(obj))`？（会丢掉函数/undefined/Symbol、Date 变字符串、循环引用直接报错）

## 四、React 场景

### 题 9：Hooks 闭包陷阱（setInterval + state）

```js
const [count, setCount] = useState(0);
useEffect(() => {
  const id = setInterval(() => {
    setCount(count + 1);   // ❌ 闭包里的 count 永远是最初渲染的值 → 永远停在 1
  }, 1000);
  return () => clearInterval(id);
}, []);
```

**根因**：`useEffect` 只跑一次，`setInterval` 回调捕获的是**首次渲染的 `count`**，不更新。

**三种修复**：
1. **函数式 setState**（最推荐）：`setCount(c => c + 1)`
2. **useRef 存最新值**：`const ref = useRef(count); ref.current = count;` 回调读 `ref.current`
3. 把 `count` 加进依赖数组（副作用：定时器会重置）

**一句话话术**："闭包陷阱是 Hooks 最常见坑——定时器/事件回调捕获了旧 state。函数式更新或 useRef 存最新值都能解，核心是**别让闭包捕获过期快照**。"

**追问**：为什么 `useRef` 能用？它为什么不会触发重渲染？（`.current` 是可变对象，改它不触发 render）

## 五、速查：额外高频手写

- **数组扁平化 + 去重**：`arr.flat(Infinity)` 后 `[...new Set(...)]`；递归实现 `flat`。
