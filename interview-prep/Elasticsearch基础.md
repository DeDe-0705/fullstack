# Elasticsearch 基础

> 面向全栈 / Java 方向的 ES 面试知识点补充。ES 底层基于 Java 写的 Lucene，所以常和 Java 技术栈搭配，但它是独立 HTTP 服务，前端/Node 也能直接调用。

---

## 一、ES 是什么

一句话：**Elasticsearch 是一个基于 Lucene 的分布式搜索引擎 + 数据分析引擎**。

- 底层：Lucene（Java 写的全文检索引擎库）
- 定位：不是关系型数据库，是「搜索引擎 + 分析引擎」
- 解决：海量数据的**全文检索、模糊匹配、聚合分析**（MySQL 的 `like` 无法高效做这些）
- 交互：独立的 HTTP 服务，通过 REST API + JSON 交互，任何语言都能用

---

## 二、倒排索引（灵魂，必考）

类比书的「索引页 / 关键词表」。区别：

- **正排索引**：文档 → 词（按文档存内容）
- **倒排索引**：词 → 文档列表（按词定位文档）

示例（分词后）：

```text
文档1：我爱学习前端
文档2：我爱 Java
文档3：学习 ES 和 Java

倒排索引：
我     → [doc1, doc2]
爱     → [doc1, doc2]
学习   → [doc1, doc3]
前端   → [doc1]
Java   → [doc2, doc3]
ES     → [doc3]
```

查 `Java` 直接拿到 `[doc2, doc3]`，O(1) 定位，而不是逐条扫描所有文档。

## 三、核心概念

| 概念 | 类比 | 说明 |
| --- | --- | --- |
| Index 索引 | 数据库的表 | 一类文档的集合 |
| Document 文档 | 一行记录 | JSON 格式 |
| Mapping 映射 | Schema | 定义字段类型 |
| Shard 分片 | 水平分表 | 索引切分，分布式存储 + 并行查询 |
| Replica 副本 | 主从备份 | 分片的拷贝，高可用 + 分担读压力 |

---

## 四、为什么快

1. **倒排索引**：词 → 文档列表，快速定位目标文档。
2. **分片并行查询**：查询请求广播到所有分片并行执行。
3. **内存缓存**：filesystem cache 加速高频数据读取。

---

## 五、ES vs MySQL

| 维度 | MySQL | ES |
| --- | --- | --- |
| 索引结构 | B+ 树 | 倒排索引 |
| 强项 | 事务、强一致、精确/范围查询 | 全文检索、模糊匹配、聚合分析 |
| 数据类型 | 结构化 | 海量、非结构化/半结构化 |
| 一致性 | 强一致 | 近实时（默认 1s refresh） |

选型：订单、用户、余额（事务）→ MySQL；商品搜索、日志检索、全文搜索、聚合分析 → ES。

## 六、使用场景

- **ELK 日志分析**：Elasticsearch + Logstash + Kibana

- **监控指标、聚合分析**

## 七、高频考点速查

1. **什么是倒排索引？** → 词 → 文档列表，支持快速全文检索。
2. **ES 为什么快？** → 倒排索引 + 分片并行 + 内存缓存。
3. **倒排索引 vs B+ 树？** → 前者全文检索，后者精确/范围查询。
4. **分片和副本的作用？** → 分片横向扩展，副本高可用 + 分担读。
5. **为什么是近实时？** → refresh 默认 1 秒，写入后 1s 内可被搜索到。
