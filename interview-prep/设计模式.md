# 设计模式

> 高级前端面试中，设计模式不是"背 23 种 GoF"，而是能不能在真实场景里说出来"为什么用这个模式、解决了什么问题"。本文收录前端高频设计模式，每个都结合实际场景。

---

## 一、创建型模式

### 1.1 单例模式（Singleton）

**核心：** 全局只有一个实例。

```js
class Singleton {
  static instance = null
  
  static getInstance() {
    if (!Singleton.instance) {
      Singleton.instance = new Singleton()
    }
    return Singleton.instance
  }
}

// 使用
const a = Singleton.getInstance()
const b = Singleton.getInstance()
console.log(a === b)  // true
```

**前端实际场景：**

```js
// 1. 全局状态管理（Vuex/Pinia store 本质是单例）
const useUserStore = defineStore('user', () => { ... })
// 多次调用 useUserStore() 返回同一个实例

// 2. 全局弹窗
class ModalManager {
  static instance = null
  static getInstance() { ... }
}
// 全局只有一个 Modal 实例，避免多个弹窗叠加

// 3. 你项目中的 AuthSDK（手撕场景题十五）
const auth = new AuthSDK()  // 全局单例，多组件共享同一份 token
```

**面试话术：** "前端最常见的单例是全局 Store（Pinia/Vuex）、全局 SDK 实例（鉴权、EventBus、WebSocket 连接）。我项目里的 AuthSDK 就是单例——多个组件共享同一份 token，刷新 token 时所有组件都受益。"

### 1.2 工厂模式（Factory）

**核心：** 把对象创建过程封装，调用方不关心怎么 new。

```js
// 简单工厂
class ButtonFactory {
  static create(type) {
    switch (type) {
      case 'primary': return new PrimaryButton()
      case 'ghost': return new GhostButton()
      case 'danger': return new DangerButton()
      default: throw new Error(`未知按钮类型：${type}`)
    }
  }
}

const btn = ButtonFactory.create('primary')
```

**前端实际场景：**

```js
// 1. 组件库的组件创建（结合你的组件库建设）
const components = { Button, Input, Select }
function createComponent(type, props) {
  const Ctor = components[type]
  return new Ctor(props)
}

// 2. 跨端适配器工厂（结合你的跨端项目）
function createApiAdapter(platform) {
  const adapters = {
    pc: pcAdapter,
    miniapp: miniappAdapter
  }
  return adapters[platform]
}

// 3. VNode 创建（Vue 内部）
// h('div', { class: 'box' }, 'hello') 就是工厂函数
```

### 1.3 建造者模式（Builder）

**核心：** 分步构建复杂对象。

```js
// 你项目中的 HTTP 请求构建
class RequestBuilder {
  constructor() {
    this.config = { headers: {} }
  }
  
  url(url) { this.config.url = url; return this }
  method(m) { this.config.method = m; return this }
  header(k, v) { this.config.headers[k] = v; return this }
  body(b) { this.config.body = JSON.stringify(b); return this }
  auth(token) { this.config.headers.Authorization = `Bearer ${token}`; return this }
  
  build() { return this.config }
}

// 链式调用
const req = new RequestBuilder()
  .url('/api/users')
  .method('POST')
  .auth(token)
  .body({ name: 'Alice' })
  .build()
```

## 二、结构型模式

### 2.1 适配器模式（Adapter）

**核心：** 让两个不兼容的接口能协同工作。

```js
// 你的跨端项目（API 适配层）
// 接口定义
interface RequestConfig {
  url: string
  method: string
  data?: any
}

// PC 适配 fetch
class FetchAdapter {
  request(config) {
    return fetch(config.url, { method: config.method, body: config.data })
      .then(r => r.json())
  }
}

// 小程序适配 Taro.request
class TaroAdapter {
  request(config) {
    return Taro.request({ ...config }).then(r => r.data)
  }
}

// 业务代码只调用统一接口
const api = platform === 'pc' ? new FetchAdapter() : new TaroAdapter()
api.request({ url: '/api/users', method: 'GET' })
```

**面试话术：** "适配器在跨端开发里非常实用——同一份业务代码，PC 调 fetch，小程序调 Taro.request。适配器把两个不兼容的 API 包装成统一接口，logic 层完全感知不到差异。"

---

### 2.2 装饰器模式（Decorator）

**核心：** 动态给对象添加职责，不改变原对象。

```js
// ES7 装饰器语法（NestJS 大量使用）
@Injectable()                    // ← 类装饰器：标记为可注入
@Controller('users')             // ← 类装饰器：定义路由
class UserController {
  @Get(':id')                    // ← 方法装饰器：定义 GET 路由
  @UseGuards(AuthGuard)          // ← 方法装饰器：加鉴权
  getUser(@Param('id') id: string) {  // ← 参数装饰器：提取参数
    return this.userService.findOne(id)
  }
}
```

**前端实际场景：**

```js
// 1. 高阶组件 HOC（React）
function withAuth(Component) {
  return function AuthenticatedComponent(props) {
    if (!isLogin()) return <Navigate to="/login" />
    return <Component {...props} />
  }
}
const ProtectedPage = withAuth(Dashboard)

// 2. 方法增强（埋点）
function log(target, key, descriptor) {
  const original = descriptor.value
  descriptor.value = function(...args) {
    console.log(`调用 ${key}，参数：`, args)
    return original.apply(this, args)
  }
}

// 3. NestJS 中你用过的所有装饰器
```

### 2.3 代理模式（Proxy）

**核心：** 控制对原对象的访问，可以加额外逻辑。

```js
// 1. Vue3 响应式（你肯定熟悉）
const proxy = new Proxy(target, {
  get(target, key, receiver) {
    track(target, key)  // 依赖收集
    return Reflect.get(target, key, receiver)
  },
  set(target, key, value, receiver) {
    trigger(target, key)  // 触发更新
    return Reflect.set(target, key, value, receiver)
  }
})

// 2. 图片懒加载代理
class ImageProxy {
  constructor(realImage) {
    this.realImage = realImage
    this.loaded = false
  }
  display() {
    if (!this.loaded) {
      console.log('加载图片...')
      this.realImage.load()
      this.loaded = true
    }
    this.realImage.display()
  }
}

// 3. 缓存代理
function memoize(fn) {
  const cache = new Map()
  return new Proxy(fn, {
    apply(target, thisArg, args) {
      const key = JSON.stringify(args)
      if (!cache.has(key)) {
        cache.set(key, Reflect.apply(target, thisArg, args))
      }
      return cache.get(key)
    }
  })
}
```

**面试话术：** "Vue3 的响应式本质就是代理模式——用 Proxy 拦截对象的 get/set，在 get 时收集依赖、set 时触发更新。这是代理模式在前端最经典的应用。"

---

### 2.4 外观模式（Facade）

**核心：** 给复杂的子系统提供一个简单的统一入口。

```js
// 你项目中的 AuthSDK 就是外观模式
class AuthSDK {
  // 内部复杂：token 存储、自动刷新、401 重试、并发去重
  // 对外只暴露简单 API
  async request(url, options) { ... }
  async login(username, password) { ... }
  logout() { ... }
}

// 业务代码用起来很简单
const res = await auth.request('/api/users')
// 不用关心内部怎么管 token、怎么 refresh
```

**前端实际场景：**
- axios：封装了 XHR/fetch/拦截器/转换器，对外只有 `axios.get()`
- jQuery：`$.ajax()` 内部封装了 XHR 的复杂流程
- 你项目里的 AuthSDK、ComponentLoader 都是外观模式

## 三、行为型模式

### 3.1 观察者模式 vs 发布订阅模式

**这是面试最容易考的一对，一定要分清。**

```
观察者模式：                    发布订阅模式：
  Subject ──→ Observer             Publisher ──→ [Event Bus] ──→ Subscriber
  直接引用                          互不认识，靠中间人
  Vue3 reactive 就这个              你项目中的 EventBus 就这个
  
  Subject 持有 observers 列表       Publisher 和 Subscriber 互不知道对方
  notify() 遍历调用                 都和 Event Bus 通信
```

```js
// 观察者模式 — Vue3 响应式内部
class Dep {
  constructor() { this.subs = new Set() }
  add(sub) { this.subs.add(sub) }
  notify() { this.subs.forEach(s => s.update()) }
}

// dep.notify() → 直接调用所有 observer 的 update()
// Subject（Dep）直接持有 Observer（ReactiveEffect）引用

// 发布订阅模式 — 你项目中的 EventBus
class EventBus {
  constructor() { this.events = new Map() }
  on(event, cb) { /* 注册 */ }
  emit(event, data) { /* 广播 */ }
  off(event, cb) { /* 注销 */ }
}

// emit 不直接调 cb，而是通过 events 中间表
// 发布者和订阅者互不认识
```

| 区别 | 观察者 | 发布订阅 |
|------|--------|----------|
| 调用方式 | Subject 直接调 Observer | 通过 EventBus 中间转 |
| 耦合度 | 紧耦合（Subject 持有 Observer 引用） | 松耦合（互不认识） |
| 典型应用 | Vue3 reactive、RxJS | EventBus、Vue2 $emit/$on |

### 3.2 策略模式（Strategy）

**核心：** 同一行为不同实现，运行时切换。

```js
// 表单校验策略
const validators = {
  required: (val) => !!val || '必填',
  email: (val) => /\S+@\S+/.test(val) || '邮箱格式错误',
  phone: (val) => /^1\d{10}$/.test(val) || '手机号格式错误',
  min: (val, len) => val.length >= len || `最少 ${len} 字符`
}

function validate(value, rules) {
  for (const rule of rules) {
    const [name, ...args] = rule
    const result = validators[name](value, ...args)
    if (result !== true) return result
  }
  return true
}

validate('test', [['required'], ['email']])
```

**前端实际场景：**
- 表单校验（不同字段不同规则）
- 排序策略（按时间/按名称/按热度）
- 渲染策略（列表视图/卡片视图/树视图）

### 3.3 状态模式（State）

**核心：** 状态变化时行为也变化——状态机。

```js
// 结合你的出入预约项目
const reservationStates = {
  pending: {
    enter() { /* 转到 entered（车辆入场） */ },
    cancel() { /* 转到 cancelled */ }
  },
  entered: {
    exit() { /* 转到 exited（车辆出厂） */ }
  },
  exited: {},
  cancelled: {}
}

class Reservation {
  constructor() { this.state = reservationStates.pending }
  setState(state) { this.state = reservationStates[state] }
  enter() { this.state.enter.call(this) }
  exit() { this.state.exit.call(this) }
  cancel() { this.state.cancel.call(this) }
}
```

**和策略模式的区别：**
- 策略模式：客户端主动选择策略
- 状态模式：状态自动驱动行为变化，客户端不感知

```js
// 可迁移到审批/订单场景
const orderStates = {
  draft: {
    submit() { /* 转到 pending */ },
    cancel() { /* 转到 cancelled */ }
  },
  pending: {
    approve() { /* 转到 approved */ },
    reject() { /* 转到 rejected */ }
  },
  approved: {
    complete() { /* 转到 completed */ }
  }
}

class Order {
  constructor() { this.state = orderStates.draft }
  setState(state) { this.state = orderStates[state] }
  submit() { this.state.submit.call(this) }
  approve() { this.state.approve.call(this) }
}
```

### 3.4 责任链模式（Chain of Responsibility）

**核心：** 请求沿着链传递，每个节点决定处理还是传给下一个。

```js
// Express 中间件就是责任链
app.use(cors())           // 节点1：处理 CORS
app.use(authMiddleware)   // 节点2：处理鉴权
app.use(logMiddleware)   // 节点3：记录日志
app.get('/users', handler) // 终点：业务处理

// NestJS 横切层也是责任链
// 请求 → Guard → Interceptor → Pipe → Controller → Interceptor → Filter
```

**前端实际场景：**
- Express/Koa 中间件
- NestJS 的 Guard/Interceptor/Pipe 链
- DOM 事件冒泡（事件沿着父链传递）

### 3.5 命令模式（Command）

**核心：** 把"做什么"封装成对象，支持撤销/重做。

```js
// 你项目中的 undo/redo 功能
class Command {
  execute() {}
  undo() {}
}

class AddUserCommand extends Command {
  constructor(user, store) { this.user = user; this.store = store }
  execute() { this.store.add(this.user) }
  undo() { this.store.remove(this.user.id) }
}

class CommandManager {
  constructor() {
    this.history = []
    this.redoStack = []
  }
  execute(cmd) {
    cmd.execute()
    this.history.push(cmd)
    this.redoStack = []
  }
  undo() {
    const cmd = this.history.pop()
    cmd.undo()
    this.redoStack.push(cmd)
  }
  redo() {
    const cmd = this.redoStack.pop()
    cmd.execute()
    this.history.push(cmd)
  }
}
```

## 四、设计模式在前端的实际应用速查

| 模式 | 前端经典应用 | 你的项目 |
|------|-------------|----------|
| **单例** | Pinia Store、全局 SDK | AuthSDK、EventBus |
| **工厂** | Vue 的 h()、React.createElement | 组件库创建 |
| **建造者** | axios 请求配置 | RequestBuilder |
| **适配器** | 跨端 API | 你的 PC/小程序 api 适配层 |
| **装饰器** | HOC、NestJS 装饰器 | NestJS 全套 |
| **代理** | Vue3 reactive | 响应式系统 |
| **外观** | axios、jQuery.ajax | AuthSDK |
| **观察者** | Vue3 reactive、RxJS | reactive dep |
| **发布订阅** | EventBus、Vue $emit | 微前端 Bus |
| **策略** | 表单校验、排序 | 校验规则 |
| **状态** | 状态机、有限自动机 | 预约单状态流转 |
| **责任链** | Express 中间件 | NestJS 横切层 |
| **命令** | undo/redo | 表单撤销 |
