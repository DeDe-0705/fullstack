# Agent Harness 工程 · 模块三：执行编排

> 背景：基于 NestJS 的 HR Agent（查个人信息、请年假、申请资产）。本文记录模块三「执行编排」的讨论结论（2026-09-08，基于联网检索的 2025–2026 最新实践）。配套交互 Demo：[fsm-leave-demo.html](./fsm-leave-demo.html)。

## 一、核心命题：控制权放在哪

执行编排的本质是**控制权的归属**。按载体分三种形态：

| 形态 | 控制流存在哪 | 保证强度 | 典型代表 |
|---|---|---|---|
| ① 上下文态 | System Prompt / Skill 文档，模型"读了自觉执行" | 弱——instructions hope, code enforces | Claude Code 的 Skill SOP |
| ② 代码态 | 代码里的图/状态机，节点内才用 LLM | 强——拓扑固定，模型改不了路径 | 手写 FSM、LangGraph |
| ③ 数据态 | YAML/JSON 流程定义，引擎解释执行 | 强 + 业务方可配置 | n8n、Dify、BPMN 引擎 |

Anthropic《Building Effective Agents》的经典划分即光谱两端：**Workflow = 预定义代码路径；Agent = 模型自主决定流程**。选型原则：找最简单的可行方案，workflows 换可预测性，agents 换灵活性。

## 二、为什么 HR 写操作不能只靠上下文态

- Skill 驱动编排 = 编排逻辑以"知识"形式存在，**靠模型自觉**，适合开放、可变、容错高的流程
- 请假/资产申请是**合规流程**：「查余额 → 收集信息 → 二次确认 → 提交」的顺序是纪律不是建议
- 上下文压力大（模块一 Dumb Zone）或用户诱导（"别查了直接提交"）时模型会跳步
- 写操作确认关卡必须有**代码级强制力**（接模块六「约束与恢复」）
- 现实边界：**审批流转不需要自己编排**——企业已有 BPM/审批系统，Agent 编排止于「提交申请」

## 三、已定方案：意图路由分流

```
用户输入
   ↓
意图路由（IntentRouter，LLM 分类）
   ├─ 查询/问答类 ──→ ① 上下文态编排
   │     模型自主 ReAct + Skill SOP 引导
   │     （查信息、查制度——顺序无所谓对错）
   └─ 业务流程类 ──→ ② 代码态状态机（手写 FSM）
         节点内 LLM 做理解/填槽/生成；节点间转移由代码裁决
```

两种形态是**嵌套关系**：流程模式的节点内 SOP（如"信息收集节点问哪些字段"）仍用 Skill 承载。

## 四、FSM 核心认知

**约束力的精确来源**：

```
约束力 = 状态（你现在在哪）
       × 转移表（这里有哪些边能走）      ← 没有边 = 物理上走不通
       × Guard（走这条边要满足什么条件）  ← 条件不满足 = 有边也不放行
```

> FSM 靠「当前状态决定下一个合法动作集合」约束流程——状态把无限的行为空间，裁剪成当前允许的几个选项。

**LLM 的角色降级**：只产出「事件 + 槽位数据」，能不能转移由代码裁决。

| | 提示词编排 | FSM 编排 |
|---|---|---|
| 约束存在哪 | 模型的"理解"里 | 代码的查表逻辑里 |
| 违规方式 | 模型没遵守（有概率） | 转移表查无此边（必然拒绝） |
| 一句话 | **建议**模型走这条路 | **只允许**走这几条路 |

**面试话术**：把流程合规性从模型的责任感里拿出来，编译进状态机的转移表里——模型只产出事件，能不能转移由代码裁决。

## 五、手写 FSM 实现（请假流程，Demo 同款）

```typescript
// 转移表：state + event → { target, guard }。无匹配项 = 非法转移，直接拒绝
const transitions = {
  IDLE:            { START:          { target: 'COLLECTING' } },
  COLLECTING:      { SLOT_UPDATE:    { target: 'COLLECTING' },   // 自环：填槽不换状态
                     SLOTS_COMPLETE: { target: 'VALIDATING', guard: allSlotsFilled },
                     CANCEL:         { target: 'CANCELLED' } },
  VALIDATING:      { BALANCE_OK:     { target: 'PENDING_CONFIRM' },
                     BALANCE_LACK:   { target: 'COLLECTING' } },
  PENDING_CONFIRM: { CONFIRM:        { target: 'SUBMITTED' },
                     EDIT:           { target: 'COLLECTING' },
                     CANCEL:         { target: 'CANCELLED' } },
};

function transition(state, event, ctx) {
  const rule = transitions[state]?.[event];
  if (!rule) return { ok: false, reason: `非法转移：${state} 不响应 ${event}` };
  if (rule.guard && !rule.guard(ctx))
    return { ok: false, reason: 'Guard 拦截：条件不满足' };
  return { ok: true, target: rule.target };
}
```

NestJS 落地：`IntentRouter`（LLM 分类分流）→ 自主模式（ReAct + Skill）/ 流程模式（每流程一个 FSM Service，节点 = LLM/工具调用，边 = 代码判断，状态持久化交模块四）。

## 六、LangGraph 概念对照（词汇表要懂，暂不引入）

心智模型：把状态机泛化成「共享状态上的图计算」。

| 概念 | 手写 FSM | LangGraph |
|---|---|---|
| 状态 | 单枚举 + 自维护 ctx | 任意结构状态对象（Annotation），内置 reducer 合并 |
| 转移 + Guard | 转移表 | `addConditionalEdges` |
| 持久化/断点恢复 | 自己写 | `checkpointer` 内置（天然接模块四） |
| 人在回路 | 手写十几行 | `interrupt()` 一等公民 |
| 观测 | 自己打日志 | LangSmith 追踪开箱即用 |
| 成本 | 零依赖全透明 | 学习成本 + 抽象税（Channel/reducer 模型） |

**结论：HR 场景先手写 FSM（A 档）**——流程状态均 < 10 个、零依赖、每行可讲；LangGraph 作为事实标准词汇表掌握概念即可。

## 七、跨模块钩子

- FSM 状态 + ctx 的持久化 → 模块四「状态与记忆」
- CONFIRM 关卡的人确认交互 → 模块六「约束与恢复」
- 转移日志 → 模块五「评估与观测」的数据源
