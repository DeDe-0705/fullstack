# Agent Harness 工程 · 模块四：状态与记忆

> 背景：基于 NestJS 的 HR Agent（查个人信息、请年假、申请资产）。本文记录模块四「状态与记忆」的讨论结论（2026-09-08，基于联网检索的 2025–2026 最新实践）。

## 一、根本区分：状态 ≠ 记忆

| | 状态 State | 记忆 Memory |
|---|---|---|
| 是什么 | 当前任务的**执行快照**：FSM state、ctx、待确认表单、scratchpad | 跨会话**提炼的知识**：偏好、事实、经验 |
| 特点 | 结构化、正确性关键、生命周期随任务 | 需要 curation：去重、冲突消解、衰减 |
| 类比 | 桌面上的草稿纸 | 大脑里记住的东西 |

两者都需要，分开治理（Anthropic 官文同样强调 memory vs state 的区分）。

## 二、三个常见误区的修正

**误区 1：「会话历史永久存 DB」= 记忆** ❌
- 会话原文存 DB 是**归档**——用途是合规审计（HR 刚需）、评估回放、故障排查
- 记忆是**提炼产物**：会话结束/关键事件后跑 memory extraction（LLM 抽取作业），把「偏好简洁回复」「审批人是张三」这类事实写进结构化记忆
- 业界原话：**历史是原始日志，记忆是筛选后的可复用信息**——不提炼就只能把几万字原文塞回上下文，回到模块一的 Context Rot

**误区 2：系统内存可以存热状态** ❌
- NestJS 多实例部署 + 随时重启 → 进程内存只能放**单请求生命周期内**的瞬时数据
- 热状态一律 Redis，没有例外

**误区 3：FSM 状态是纯临时的** ❌
- 请假流程可能**跨天**（今天填一半明天继续）
- Redis 存热状态（带 TTL）+ **关键节点写 checkpoint 到 PG**（= LangGraph checkpointer 概念，手写 FSM 同样要）

## 三、记忆标准分类学（2025–2026 词汇表）

| 类型 | 回答什么问题 | 特点 | HR Agent 例子 |
|---|---|---|---|
| **工作记忆**（scratchpad） | 当前任务想到哪了 | 默认不持久化，随任务消亡 | 请假表单已填的 3 个槽位 |
| **情景记忆**（episodic） | "发生过什么" | 带时间戳，**会衰减** | "上周申请显示器被驳回" |
| **语义记忆**（semantic） | "什么是真的" | 稳定事实，改变时**就地更新不追加**（追加会积累矛盾） | "审批人是张三" |
| **程序记忆**（procedural） | "怎么做" | 技能/SOP 进化 | 请假 SOP（= 我们的 Skill 文件） |

**分类测试**：问哪个查询应该检索到它。"上次请假什么时候"→情景；"审批人是谁"→语义；"怎么办请假"→程序。

**写入路径**：写入时打类型标签（kind 字段），驱动索引方式、评分、衰减策略。HR 场景必须加：**PII 过滤 + 敏感黑名单 + 用户可查看/删除**（工资、健康状况绝不进记忆）。

**记忆系统四大坑**（业界总结）：
1. 把聊天历史等同于记忆
2. 只加 read path，写入/合并策略粗糙 → 检索结果"看起来对、用起来乱"
3. 没有统一 Memory Schema → 检索、合并、淘汰全是补丁
4. 自动写入敏感信息，用户不可见不可删

## 四、落地：HR Agent 存储映射表

| 数据 | 归属 | 存储 | 生命周期 |
|---|---|---|---|
| FSM state + ctx | 状态 | Redis（热，TTL）+ **PG checkpoint**（跨天恢复） | 任务完成/取消后归档 |
| 会话消息原文 | 归档 | Redis list（热）→ PG（合规审计） | 永久归档 |
| 工具输出 / RAG 原文 | 状态 | **不持久化**，消息存引用 ID 按需重取（模块二 just-in-time 闭环） | 随会话 |
| scratchpad / plan | 状态 | Redis 随会话；**交接文档 → PG**（接模块一 context reset） | 任务级 |
| 语义/情景记忆 | 记忆 | PG + 向量索引，带 kind/来源/敏感度标签 | 长期，可衰减可删除 |
| 程序记忆 | 记忆 | Skill 文件（工程资产，不走运行时存储） | 随版本 |

## 五、NestJS 落地结构

- `SessionStateService`：Redis 热状态读写（FSM state + ctx + scratchpad），带 TTL
- `CheckpointService`：FSM 关键节点写 PG，恢复时 Redis miss → 查 PG 重建
- `MemoryExtractionService`：会话结束触发的 LLM 抽取作业（异步队列），输出带 kind 标签的结构化记忆，过 PII 过滤器后落 PG
- `MemoryQueryService`：语义检索 + 时间衰减评分，供模块一 PromptBuilder 注入
- 会话归档：Redis list → 会话结束落 PG（合规审计）

## 六、待对齐决策

1. **长期记忆第一期范围**：推荐只做语义记忆小集合（用户偏好 + 组织关系快照）+ 会话归档；情景记忆和衰减机制后置（curation 是深水区，做砸反而污染上下文）—— 待确认
2. **FSM checkpoint 频率**：推荐每次转移都写 PG（HR 流程 QPS 低，写放大可接受，恢复语义最简单）—— 待确认
