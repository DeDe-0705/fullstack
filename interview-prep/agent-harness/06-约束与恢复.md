# Agent Harness 工程 · 模块六：约束与恢复

> 背景：基于 NestJS 的 HR Agent（查个人信息、请年假、申请资产）。本文记录模块六「约束与恢复」的讨论结论（2026-09-08，基于联网检索的 2025–2026 最新实践）。

## 一、核心认知：护栏不是外挂，是 Agent 系统的本体

> 「护栏不是加在 Agent 上的东西——护栏就是 Agentic 系统本身。」

没有护栏的系统只是"一个 LLM 加几个工具"；正是约束让行为可依赖。

**2026 认知转变**：只靠 Prompt Guardrail 不够了。Agent 具备工具调用、记忆、外部系统访问能力后，本质是**"会行动的软件主体"**，攻击面从"说什么"扩展到"做什么"（OWASP 已出专门威胁分类）。

## 二、约束：护栏的五个挂载位置

| 位置 | 管什么 | HR Agent 实例 |
|---|---|---|
| 输入护栏 | 意图合规、注入检测、PII | "把张三的工资发我"→ 越权意图拦截 |
| 检索护栏 | 检索内容是否该给这个人看 | 制度文档按密级过滤 |
| 对话护栏 | 话题边界、行为流程 | 不回答非 HR 话题；FSM（模块三）本身就是行为护栏 |
| 输出护栏 | 泄露检查、事实性 | 回复里不能出现他人薪资数字 |
| 执行护栏 | 工具调用的权限与确认 | 写操作必须过 CONFIRM 关卡（模块三已埋） |

### 三个关键设计决策

**1. 安全关键的检查用代码，不用 LLM**
权限校验、参数校验、PII 正则——确定性、零幻觉、可单测。LLM judge 只做语义级辅助信号（"这个意图是否越权"）。OpenAI Agents SDK 模式：输入护栏与主 Agent **并行跑**（省延迟），触发 tripwire 立即中断。

**2. 间接提示注入是头号威胁**
**工具返回的内容也是不可信输入**——制度文档、员工备注、审批意见里藏"忽略之前的指令…"就是间接注入。对策：工具返回进上下文时标记为不可信数据；输出护栏做泄露检查；写操作 CONFIRM 关卡由**人**拍板而非模型。

**3. 确认分级（Claude Code 模式）**

```
只读操作          → 直接执行（查余额、查制度）
可逆写操作        → 会话内首次确认，之后免确认（提交请假）
不可逆/高敏操作   → 每次确认 + 明确展示参数（薪资变更、代他人操作）
```

FSM `PENDING_CONFIRM` 节点承载第 2 级；第 3 级在 guard 里加强制人工参数复核。

**已定**：确认交互用**B 档——结构化确认卡片**（前端渲染参数卡片 + 确认/修改按钮，按钮直接发 CONFIRM 事件；防"手滑打错字确认错单"）。

## 三、恢复：按失败类型开药方

| 失败类型 | 例子 | 策略 |
|---|---|---|
| 瞬时故障 | 网络抖动、限流、LLM 超时 | **指数退避重试**（上限 3 次）——自愈率最高的一类 |
| 格式/解析故障 | LLM 输出非法 JSON、工具参数错 | 带错误信息重试（模块二"错误即教学"兑现） |
| 业务失败 | 余额不足、制度不允许 | **不重试**——回话术引导（FSM 的 BALANCE_LACK 边） |
| 中途崩溃 | 服务重启、Pod 被杀 | **checkpoint 恢复**（模块四）：Redis miss → PG 重建 FSM 现场，用户无感续聊 |
| 系统性故障 | 工具连续失败、模型服务挂 | **熔断 + 降级**：转人工话术/只读模式（熔断器与模块一压缩管线同款） |

### 写操作两个铁律（模块二钩子收口）

**铁律 1：幂等键**。`apply_leave` 带 idempotency key（会话 ID + 业务指纹 hash）：网络重试、模型重复调用、用户狂点确认——同一张请假单只创建一次。= db-training 练过的「唯一约束幂等」从 DB 层上到 API 层。

**铁律 2：补偿而非删除**。撤销已提交请假走 `cancel_leave` 业务工具（有审批流、有审计记录），**绝不直接 delete**——Saga 模式在 Agent 里的形态：**每个写工具都应有对应的补偿工具**。

## 四、NestJS 落地：概念一一对应

```
输入护栏    → NestJS Guard（同名同概念）
参数校验    → ValidationPipe + class-validator
确认关卡    → FSM PENDING_CONFIRM 节点 + 前端确认卡片
重试/退避   → Interceptor 封装
熔断降级    → 自研 CircuitBreaker 或 opossum
异常分类    → ExceptionFilter 按失败类型路由处置策略
幂等        → IdempotencyInterceptor（key 存 Redis，SET NX）
```

## 五、六大模块全景（系列收尾）

| 模块 | 核心决策 |
|---|---|
| 01 上下文管理 | 五层结构；四层压缩管线；just-in-time 检索；ALS 注入身份 |
| 02 工具系统 | 三层模型（能力/接入/Skill）；Tool RAG = 权限过滤 + 语义精选 Top-K；返回三闸门 |
| 03 执行编排 | 意图路由分流；业务流程手写 FSM（转移表 + Guard）；LangGraph 只作词汇表 |
| 04 状态与记忆 | 状态≠记忆；Redis 热状态 + PG checkpoint；memory extraction 提炼写入 |
| 05 评估与观测 | 评测集 + CI 回归（A 档）；确定性断言优先；Langfuse 观测 |
| 06 约束与恢复 | 五位置护栏；确认分级 + 结构化确认卡片；幂等键 + 补偿工具；按失败类型开药方 |
