HTTP 缓存决策流程

浏览器请求资源时的完整缓存判断链路

判断节点
直接使用缓存
304 协商缓存
200 获取新内容
浏览器发起请求
GET /app.js
检查 Cache-Control
是否有 no-store？
是 → 直连服务器
否 ↓
强缓存检查
max-age 或 Expires 是否过期？
未过期 →
过期 ↓
✅ 直接使用缓存
200 (from disk/memory cache)
协商缓存检查
有 ETag 或 Last-Modified？
无 →
有 ↓
200 获取新内容
更新本地缓存
带条件头发送请求
If-None-Match / If-Modified-Since
资源未变 →
资源变了 ↓
304 Not Modified
使用本地缓存，更新缓存时间
200 返回新内容
更新 ETag + 缓存

头部速查

Cache-Control: max-age=3600缓存 3600 秒（强缓存）
Cache-Control: no-cache每次验证（走协商缓存）
Cache-Control: no-store完全不缓存
ETag: "abc123"内容哈希，精确验证
Last-Modified: Wed, 21 Jul 2026...文件修改时间，秒级精度
